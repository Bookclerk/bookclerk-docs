### Model


One storefront title fetched for one Discover subject (`DeriveEntityModel`).

Rows for a `(subject_key, source)` pair are replaced together when that
store's fetch for the subject finishes, so one slow store never erases
another store's results.

**Fields**

- `id`: Surrogate primary key assigned by the database.
- `subject_key`: Discover subject the candidate was fetched for (`operator`, `user:<id>`, `portal:<id>`).
- `source`: Storefront plugin id that returned the title (`audible`, `chirp`, …).
- `candidate_key`: Identity key of the candidate within its subject and store (ASIN / ISBN / product key).
- `seed_scope`: Which seeds produced the row: `own` (the subject's taste) or `household`.
- `candidate_json`: The candidate itself as JSON (`bookclerk_discover::StorefrontCandidate`).
- `fetched_at`: RFC 3339 timestamp of the store fetch that produced the row.
